这是 B2.5 终态关闭之后的工程与研究设计修复。它不会重开 B2.5，不会放宽其冻结门槛，不会对已经完成的矩阵评分或排名，不会生成赛事结果，不会复用启动授权，也不会修改产品默认方案。权威历史终态仍是 [`product_bakeoff_b25_failed_closed_aggregate.json`](../../artifacts/product_bakeoff_b25/product_bakeoff_b25_failed_closed_aggregate.json)。

公开修复汇总为 [`product_bakeoff_postcloseout_determinism_repair.json`](../../artifacts/product_bakeoff_determinism_repair/product_bakeoff_postcloseout_determinism_repair.json)。

## 工程审查发现

审查发现了多处会让有界检索结果继承进程内顺序或调用方输入顺序的实现：

- Tantivy `TopDocs` 使用文档地址打破同分。临时和持久化 BM25 过去只抓取固定倍数的候选，并在稳定的路径/范围排序看到完整边界同分集合之前截断。
- RRF 使用无序映射累积精确单元，并在遍历时修改映射来折叠包含范围。一个宽范围同时覆盖多个互不包含的窄范围时，整票可能转移给哈希遍历中最先出现的子范围。
- 图配置边上限直接从 `HashSet` 选择；候选很多时，不同进程可能得到不同的有界子集。
- 文本、正则符号、AST 符号和上下文图种子在达到上限时可能继承输入顺序。
- 历史 B2/B2.4/B2.5 校验器把冻结源摘要重新绑定到当前检出。关闭后的合法源码修复会因此被误报成历史制品漂移。

## 工程修复

BM25 现在会扩展收集，直到过采样边界上的整组同分都可见；随后完成实体化、精确单元去重，按原生分数以及稳定的路径/范围/内容键排序，最后才应用上限。普通持久化搜索与可复用索引句柄共用同一个实现。临时 BM25 独立采用同一规则，因为 retrieval 与 index crate 目前没有共享 Tantivy 工具层。

RRF 现在先排序通道输入，使用 `BTreeMap` 累积精确单元，规范化元数据，并基于不可变键快照计算包含关系。只有一个最窄后代时，祖先票全部转入该后代；存在多个互不包含的最窄后代时，祖先票等分，既保持 RRF 总票数，也不人为制造“最左边”或“哈希顺序”赢家。

图记录、节点、边、配置候选和序列化的边类型计数都具有稳定顺序。文本、正则符号、AST 符号和上下文图种子的上限也都加入了显式路径同分规则。

终态归档校验器以规范 JSON 锁定 B2 到 B2.5 的 15 个公开制品，在适用时验证规范自摘要，并检查公开的跨阶段绑定。它明确不会再拿历史源码包与当前 `HEAD` 比较。

## 可比性门槛审查

从原则上看，历史精确语义哈希覆盖面大于冻结评分器：候选原生分数与顺序、重复范围的切分方式、摘录、通道、解释文字和状态原因即使不同，也可能保持所有评分输入等价。把每一种此类诊断差异都直接视为“不可评分”，确实过严。

[`product_bakeoff_postcloseout_comparability.py`](../../eval/product_bakeoff_postcloseout_comparability.py) 给未来独立预注册实验定义了不读取 oracle 的评分等价投影：

- context 观测保留准入包络、候选集合是否为空、pack 状态、证据行并集、目标行并集以及 support 集合是否为空；
- support 观测保留准入包络，以及关系类型、父目标、support 路径和 support 行并集；
- 源码当前性、可评分性、同 arm 谱系、公平性和 provider 隔离仍是彼此独立的强制门槛。

未来的评分前重复性门槛和评分器内部的重复单元归一化必须冻结并使用同一个投影。只改前者而保留评分器里的第二层精确哈希拒绝，会留下一个隐藏冲突。

这项设计结论并不能证明历史 B2.5 失败只是诊断差异。B2.5 的冻结决定不会被追溯改写，至今仍不存在 B2.5 分数或排名。
