# 产品栈对比 B4 独立重复协议

日期：2026-07-18

状态：`product_bakeoff_b4_independent_replication_protocol_frozen_no_runtime_no_holdout_no_execution`

B4 是一个全新的未来实验，不是 B3 的延续或重新解释。B3 公开聚合只用于把问题收敛到三个实验臂并定义敏感性场景。B3 的仓库、任务、查询、oracle、治疗输出、排名和 launch authorization 均不复用，B3 也不计作确认性重复。

机器可读预注册为 [`product_bakeoff_b4_protocol_report.json`](../../artifacts/product_bakeoff_b4_protocol/product_bakeoff_b4_protocol_report.json)。

## 独立重复结构

B4 在十二个互不重叠的面板上比较 S0、S1 和 S4。每个面板在每个“语言 × 规模”槽位各使用一个全新仓库，共 12 个仓库；每个仓库提供四种冻结任务角色。因此完整设计包含 144 个仓库簇和 576 个配对逻辑任务，每个任务都接受三个实验臂。

仓库才是独立质量簇。B4 不再重复运行同一任务并把这些重复误算为额外证据。每个“仓库 × 实验臂”只执行一个正式生命周期：一个冷任务和三个热任务，而且冷任务角色在每个面板内精确平衡。这样正式计划只需 432 次索引构建、2,160 个逻辑组和 2,160 条逻辑记录，同时保留真正修复 B3 重复性缺陷所需的独立面板。

全部仓库、任务、查询、oracle、面板分配、冷热分配和调度都必须在第一条治疗观测前完成 authoring 和冻结。B2 至 B3 用过的所有仓库帧均被排除，各面板不得重叠，authoring 接受规则也不得依赖任何实验臂输出。

三个实验臂使用全部六种处理顺序。每个面板内，六种顺序不仅在冷任务和热任务中分别精确平衡，也在每一种任务角色中分别精确平衡；因此在冷热分层执行面上，实验臂位置与一阶前序效应也精确平衡。

## 分析与决策规则

确认性主要结果是配对任务成功差。配对任务效用净胜率、状态/目标成功和 context F0.5 是关键次要估计与排名结果，不是额外确认性检验。任务效用采用字典序：任务成功、无有害证据、状态/目标成功、context F0.5，而不是不透明的加权总分。推断目标是十二个冻结面板上的平均效应，而不是不受约束的总体效应。点估计与普通 95% 估计区间始终发布。主要结果的两个预先计划比较为 S1 对 S0、S4 对 S0，采用 Bonferroni 控制，每个比较使用双侧 alpha 0.025，并用同时 97.5% 区间执行确认性门槛。

十二个面板中至少八个面板的点估计必须为正。在正负方向等概率的零假设下，八个及以上正向面板的尾概率为 0.193847，因此它明确只是异质性保护条件，不是第二个显著性检验。家族错误率由聚合调整区间控制；零效应面板不计为正向。

每个终态结果都必须先对三个实验臂全部排名，再应用部署门槛。质量排名依次比较任务成功率、有害证据率、状态/目标成功和 context F0.5；资源排名依次比较 warm-query 几何均值和 peak-RSS P95。完全相同的结果共享 competition rank。终态还必须发布配对效应、两种区间、面板方向计数、门槛结果和四维质量/资源 Pareto frontier。门槛失败不能删除估计，也不能生成空排名。

S1 属于默认候选轨，S4 属于可选高召回轨。两者都要求任务成功点效应至少六个百分点、同时 97.5% 区间下界为正、至少八个正向面板，并且有害证据风险差的同时区间上界不超过两个百分点。S1 的 warm-query 95% 比率上界不得超过 1.20，peak RSS 不得超过 1.15；S4 的界限为 2.10 和 1.25。这些只是资格门槛，不能替代公开比较；任何晋级仍需单独的全新 Phase C 验证。

## 有界存储与执行

B4 不要求 144 个仓库同时保持展开。authoring 每次只克隆一个候选，生成内容绑定的紧凑源码快照，然后在处理下一个候选前删除克隆；Git 历史、依赖缓存和构建输出均不长期保留。正式执行通过有界 lane 流式读取冻结快照，每个 lane 最多展开一个仓库；结果先持久化追加，再回收该 lane 的 scratch。

lane 数量、CPU affinity 和实测 working-set 额度必须在治疗前完成 qualification 与冻结，对每个实验臂完全一致，输出开始后不得自适应增加并发。磁盘 admission 由冻结快照实测大小和已 qualification 的 runner working set 推导，不再设置任意固定空闲磁盘门槛；该实验也不需要 GPU。

## 功效与样本量敏感性

确定性 Monte Carlo 模型评估联合质量门槛，即同时评估显著性、实际效应大小和面板方向一致性，而不只评估显著性。它组合七种效应、0.05/0.15/0.25 三种仓库 ICC，以及 0/4/8 个百分点三种以真实均值为中心的面板间效应离散度，共 63 个场景。每个场景执行 2,000 次模拟并发布 Monte Carlo 区间。由于 B3 未公开任务级配对不一致率，模型保守采用 0.50。资源与有害证据门槛没有可辩护的规划分布，因此不伪造其功效估计。

当真实平均效应为十二个百分点时，聚合检验功效为 0.793–0.947，联合质量门槛功效为 0.777–0.929；九个 nuisance 场景中六个达到至少 0.80，预注册的中等 nuisance 子集最低为 0.849。因此协议不宣称“所有场景均有 80% 功效”，而是直接公开不利场景敏感性。

冻结的样本量比较解释了为何 B4 选择十二个面板。在十二面板预注册场景中功效最低的 nuisance 组合下，十二个面板的联合质量功效估计为 0.777，十八个面板为 0.925；但十八个面板需要 216 个仓库和 3,240 条记录，正式工作量增加 50%。由于 B4 即使未过资格门槛也始终发布估计、排名和 Pareto frontier，而且晋级仍需全新 Phase C 证据，因此不为覆盖一个最不利且尚无法识别的 nuisance 场景强制增加这 50% 成本。

## 当前边界

当前只有协议和合成验证。runner、scorer、publication、runtime qualification、全新私有留出集、readiness、launch authorization 和治疗执行均未获授权。下一步是在本地实现并故障测试这些控制面；本检查点不需要算力服务器。
