# Product Stack Bakeoff — Phase A

Date: 2026-07-13

## Product-oriented pivot

OpenLocus-Lab is now the experimental comparison ground for selecting the future product's default algorithm stack, optional tiers, fallbacks, supported languages/repository sizes, resource envelope, and stable integration contract. No near-term model training is planned. Future production implementation will live in a separate folder/repository after the lab produces a landing specification.

The bakeoff compares algorithms/components through canonical candidate and context-pack schemas, not whole competing agents. Historical lab work remains; routes are not deleted just because they lose the product bakeoff.

## Fairness contract

Comparable arms must match exactly on the fairness fingerprint: schema/run-cell/task/snapshot/source-visibility IDs and actual digests, query, language/task family, adapter repetition, closed cold/warm cache state, interaction mode and lineage, candidate/evidence/target/support/rendered-context/episode/step caps, timeout, renderer/materializer/budget-estimator versions, and the writable-state-root id. Adapter identity and measured resources are excluded. The run spec is bound to the actual frozen snapshot digests; mismatch is rejected. The full Cartesian comparison-matrix validator enforces adapter x logical-cell x repetition x cache x interaction-step completeness, rejects missing/unexpected/duplicate keys, compares fairness fingerprints within exact logical cells, and exercises real repetitions 1/2/3 with FULL semantic-envelope determinism (record/result/pack status, canonical failure category, capability ledger, then hashes for accepted groups; repetition identity excluded from canonical hashes). An accepted->rejected->accepted adversarial record case proves that a "middle" repetition rejected is detected as semantic-envelope drift.

## Two-step interaction

Minimal interaction support is frozen: `interaction_mode = one_shot | two_step`, `operation = context | support`; episode/request lineage via `episode_id`, `request_id`, `parent_result_id`, `bound_target_id`. A real synthetic context->support episode is exercised with a registered parent/target (stable id derived from the actual materialized target via `stable_target_id`), invariant lineage (actual target, task, episode, snapshot/visibility/renderer/materializer/estimator identity, invariant episode caps, parent step), actual cumulative episode-budget accounting, and adversarial unknown-parent / unknown-target / cross-task / cross-episode / cross-snapshot / altered-cap / repeated-step / budget-overrun cases. The registry keeps a two-record context->support scope, not a generic workflow engine. Outcome/patch schemas remain deferred.

## Adapter lifecycle

The minimal lifecycle contract: optional `prepare` and `index` hooks, required `query` hook, harness-owned phase timing (setup/index/query/materialize/render), declared persistent-state behaviour (`stateless` / `cold_rebuild` / `warm_reuse`), and explicit cold/warm reuse semantics. In `warm` cache_state with `warm_reuse` persistent-state behaviour, prepare and index are skipped (state assumed to exist); in `cold` cache_state or with `stateless`/`cold_rebuild`, prepare and index are called if present. Unattempted phases have `None` timing in the ResourceSample. This is not a plugin framework; the common harness does all source reading/materialization/rendering, adapters only emit untrusted candidates/binding via the query hook.

v4 stateful lifecycle tests (non-vacuous): cold writes a state marker into `writable_state_root`; warm on the SAME snapshot/root observes the marker while skipping rebuild (proving prior state was actually built and reused); v5: warm-without-state is an explicit REJECTED result (the stateful query returns a failed result when the warm marker is absent; canonical failure category `adapter_exception:FailedResult`; no successful pack is produced); `stateless` and `cold_rebuild` warm requests actually run configured hooks (stateless always rebuilds; cold_rebuild always rebuilds the index). Intermediate immutable-source scans after prepare, after index, and after query catch mutate->restore patterns that would mask a mutation if only the final scan ran.

## Common safe path policy

One common safe path policy (`_validate_safe_path_under_root`) is applied before any snapshot read or directory creation, reused across manifest/snapshot/tree/candidate/writable validation. It validates: (1) lexical relative path (no NUL, UNC, absolute, drive, traversal, backslash, dot-only); v5: the ORIGINAL LEXICAL path components beneath the root are walked (not resolved parts) so an in-root parent symlink whose target stays inside root is also rejected — `full.resolve()` would dereference such a symlink and hide it; a lexical path not beneath root is rejected before the resolved confinement check; (2) all path components beneath the resolved root are checked for symlinks (rejects parent symlinks AND symlinked path components); (3) resolved confinement (the fully resolved path must stay beneath the resolved source root). Out-of-root writable-state roots are rejected WITHOUT being created on disk (confinement is validated before `mkdir`). v5: writable-state root equal to source root, ancestor/equal of any visible path, or containing any visible path is rejected BEFORE `mkdir` (root and root/src overlap probes exercised). A symlinked-parent escape fixture AND an in-root symlinked-parent fixture (target still inside root) are exercised on symlink-capable CI (Windows without symlink privilege explicitly skips; Linux CI must exercise both).

## Fail-closed record validation

`validate_run_record` is fail-closed and used by BOTH `validate_comparison_matrix` AND `aggregate_public_report`. It rejects: vocab/type/count/hash/resource/status inconsistencies; pre-execution resource presence (a prevalidation rejection must not carry a `ResourceSample`); and any unsafe string in `failure_category`. Adapter exception MESSAGE text and raw adapter-authored failure categories NEVER reach public keys; the harness maps to canonical categories using stage + exception TYPE only (`adapter_exception:RuntimeError`, `adapter_exception:PartialResult`, `adapter_exception:FailedResult`, `adapter_timeout`, `non_adapter_result`, etc.). Records that fail `validate_run_record` are counted as rejected-by-validation with a canonical `record_validation:invalid_record` marker and NEVER reach the accepted surface. v9: rejected records MUST carry an EMPTY `capability_ledger_summary` — only accepted records may publish a validated ledger. Public capability counts (`capability_status_counts` / `capability_ledger_entry_count`) are derived from ACCEPTED records only and reconcile. v9: an accepted record with `candidate_count > 0` requires `capability_ledger_summary["candidate_search"] == "executed"` (record defense complementing the in-run honesty check). The public report carries a `capability_ledger_entry_count` aggregate scalar = `sum(capability_status_counts.values())` over accepted records only; `validate_written_report` enforces nonnegative int + exact sum equality, with tampered-bucket and tampered-scalar adversarial cases rejected.

## v9 closure — full initial source-tree freeze, pre-hook infrastructure scan, deadline-inclusive transport, capability-ledger trust

Phase A v9 closes three canonical fairness issues without adding algorithms, datasets, providers, product repo code, generic plugin/executor frameworks, or private runs:

- **Full initial source-tree freeze:** `materialize_snapshot` materializes the declaration iterable once (no `set` collapse), requires nonempty strings, rejects duplicate declarations, lexical-validates every path, requires the root to preexist as a real non-link/non-reparse directory, validates the writable-state root without creating it (strict in-root confinement, no symlink/junction/reparse components, no overlap with declared files), enumerates the FULL source tree (via one `_enumerate_source_tree` helper shared by both `materialize_snapshot` and `scan_visible_tree`) BEFORE `mkdir` using `os.walk(topdown=True, followlinks=False)` with sorted names and `onerror` raising, requires EXACT set equality declarations == enumeration (any undeclared or missing source rejects), builds manifest/tree digests from this enumeration (not declaration-only rereads), and ONLY after equality creates the writable-state root then revalidates identity/confinement/type. Declarations are kept meaningful and are NEVER derived/repaired from the filesystem. `scan_visible_tree` calls the same enumerator and compares the full (path, digest, size) tuple, path set, per-file digest, per-file size, and tree digest; no silent walk errors. Symlink/reparse/special files and every traversal/lstat/open/read/stat error are rejected; bytes are hashed with before/after identity/size checks. Only the exact lexical writable-state-root subtree may be excluded (when it exists); an absent WSR is not traversed.
- **Pre-hook infrastructure scan:** `run_adapter` runs `assert_snapshot_unchanged` after request/descriptor/lineage validation and immediately before the FIRST attempted prepare/index/query. If this fails BEFORE any hook starts, it raises `HarnessInfrastructureError` (aborting the whole bakeoff — NO rejected record). This is the last harness operation before spawn. Mutations detected AFTER a hook starts remain adapter rejections.
- **Deadline-inclusive transport (current v12 semantics):** `_execute_stage_isolated` uses a unidirectional `multiprocessing.Pipe(duplex=False)` with `send_bytes`/bounded `recv_bytes`, a closed strict-JSON envelope, `MAX_STAGE_WIRE_BYTES = 8*1024*1024`, and an absolute deadline beginning BEFORE process start and covering receive, decode, validation, and canonical reconstruction. The parent uses one receiver thread plus a one-slot queue and rechecks the deadline after each payload-processing stage. On timeout it terminates/kills/reaps the child, closes the pipe, joins the receiver, and verifies that neither child nor thread remains alive. Child EOF, exit, no-send/send failure, oversized or malformed frames, and ambiguous receive errors are adapter-scoped `process_died` or `malformed`; they cannot author a whole-bakeoff infrastructure abort. Only demonstrably parent-local setup/start, poll/handle, cleanup/reap, or receiver-thread failures raise `HarnessInfrastructureError`. `_reap_process` attempts all cleanup and verifies that the child is no longer alive. Spawn-per-stage is retained; there is no executor. This bullet records the current v12 contract; the v10 history and its v11/v12 supersession are documented below.
- **Capability-ledger trust:** No forgeable validated boolean is added. Every rejected record carries `capability_ledger_summary={}`; `validate_run_record` rejects any rejected record with a nonempty ledger. Accepted records only may publish a validated ledger. Public capability counts/count entries come from accepted records only and reconcile. Ordering: `validate_adapter_result` (closed shape/bindings/descriptor ledger/candidates/fallback) THEN `validate_capability_ledger_honesty` (immediately, BEFORE materialization) THEN hash/materialize/pack/register/copy ledger. `candidate_search` honesty: nonempty candidates require `candidate_search=executed`; NO converse (executed may return zero). Accepted + `candidate_count>0` requires the summary `candidate_search=executed` (record defense).
- **Oracle visible_files preflight:** `TaskOracle.validate(visible_files=...)` checks that every acceptable target span path, support record support_path + target_path, and must_not_primary_path belongs to the frozen visible set. The oracle stays scorer-only (no source reads, never imported during the run phase).

## v10 closure — special-file rejection before read, receive bound before allocation, genuine worker send failure classification

Phase A v10 closes three narrow gaps in already-claimed v9 guarantees without adding algorithms, datasets, providers, product repo code, generic plugin/executor frameworks, or private runs:

- **Special-file rejection before read:** `_enumerate_source_tree` rejects special files (FIFO, socket, device, directory, unknown file types) BEFORE `read_bytes` via `stat.S_ISREG(st_mode)` on the `os.lstat` result — without opening or reading the entry. After read, the after-lstat must still be a regular file with identical `(st_dev, st_ino, st_mode, st_size)` identity; any replacement/mode/type/size change rejects. Available identity fields are compared consistently (`st_ino` may be 0 on some Windows filesystems; both sides are 0, so the comparison still holds). Root and writable-state-root existing type validation fail closed on lstat errors. A real POSIX FIFO adversarial test (when `os.mkfifo` is available) proves snapshot construction rejects promptly without opening the FIFO; on Windows where FIFO is unavailable, the feature is honestly skipped and a mocked special `st_mode` path is tested.
- **Receive bound before allocation:** the parent receiver calls `recv_bytes(maxlength=MAX_STAGE_WIRE_BYTES)` so the wire bound is enforced BEFORE full payload allocation (the stdlib reads the length header first and raises `OSError` without allocating the oversized body). At-bound (exactly `MAX_STAGE_WIRE_BYTES`) succeeds; worker-side over-bound remains a small malformed envelope. v11: parent-observed over-bound and ambiguous receive `OSError` are classified as adapter-scoped `malformed` (NEVER infrastructure failure) because a child can induce them and the stdlib oversize condition cannot be reliably distinguished from a genuine pipe `OSError` without parsing exception message text. FakePipe tests assert `maxlength` is actually passed and verify boundary behavior (at-bound succeeds, over-bound raises).
- **Genuine worker send failure classification (v10, superseded by v11/v12):** v10 introduced a dedicated `WORKER_TRANSPORT_FAILURE_EXIT_CODE = 73` and a `transport_failure` envelope status to classify genuine worker send failure as infrastructure failure. v11 REMOVED this entire mechanism (see the v11 closure section below) because it was forgeable: an adapter could call `os._exit(73)` to author an infra abort. v11 classifies every child EOF/exit code as adapter-scoped `process_died` (never `HarnessInfrastructureError`). v12 keeps the v11 boundary and narrows the doc claims: the existing `close_without_send` / `os._exit(...)` tests are EOF / no-send tests (the child closes the pipe or exits before sending), NOT tests that force `conn.send_bytes` to raise inside a real spawned worker. The docs no longer claim a "real send failure test"; the actual classification proven is child EOF / no-send => `process_died`.

## v11 closure — eliminate pickle from the adapter-controlled wire; remove forgeable whole-bakeoff abort signals

Phase A v11 closes two canonical RCE/forgeability gaps in the v10 stage transport without adding algorithms, datasets, providers, product repo code, generic plugin/executor frameworks, or private runs:

- **Bounded strict JSON primitive wire (NO pickle anywhere on the run-phase wire):** the child serializes ONLY a closed JSON primitive envelope `{"v": 1, "status": <ok|error|malformed>, "payload": <closed_payload_or_null>, "error": <str_or_null>}` via `json.dumps` + `conn.send_bytes`. UTF-8 JSON bytes, compact/deterministic encoding (`sort_keys=True`, `separators=(",", ":")`). No adapter-defined encoder/default/object_hook/repr/string conversion is used. Before encoding, the returned canonical `AdapterResult` is normalized into a new plain builtin `dict`/`list`/`scalar` tree under EXACT type checks (`type(x) is AdapterResult` etc., NOT `isinstance` accepting subclasses that could override behavior). All nested `Candidate`/`BindingProposal`/`FallbackRecord`/capability-ledger values are copied field-by-field under closed schemas with primitive exact types, finite numbers, bounded strings/counts/depth. Reject/emit small malformed envelope if exact canonical dataclass types are not satisfied, any unknown/nonprimitive/mapping-subclass/custom object is encountered, property access fails, JSON encode fails, or the normalized envelope would exceed `MAX_STAGE_WIRE_BYTES`. Lifecycle ok returns exact `null`. The exception envelope carries only trusted `type(e).__name__` (itself bounded/validated); the adapter exception MESSAGE text NEVER crosses the wire. The outer wire envelope is an exact closed JSON object with trusted `v`/`status`/`payload`/`error` fields; ambiguous bool-as-int is avoided (`type(x) is int/float/bool` semantics); all floats are finite; explicit max depths/counts/string lengths are consistent with existing contract maxima.
- **Strict parent-side decode + canonical reconstruction (NO `pickle.loads`/`pickle.dumps`/pickle import in run-phase modules):** the parent receives bytes with the existing hard allocation bound (`recv_bytes(maxlength=MAX_STAGE_WIRE_BYTES)`), strict UTF-8 decodes (rejecting invalid UTF-8 and embedded NUL), then `json.loads` with `parse_constant` rejection (NaN/Infinity) AND an `object_pairs_hook` that rejects duplicate keys at every object level. No `object_hook` capable of constructing arbitrary types is used. Rejects: invalid UTF-8, trailing/multiple docs, duplicate keys at any level, NaN/Infinity, wrong primitive types, extra/missing keys, excessive depth/count/string length, and closed-schema violations. The parent reconstructs exact canonical dataclasses (`AdapterResult`, `Candidate`, `BindingProposal`, `SupportBinding`, `FallbackRecord`) field-by-field in trusted parent code, then runs existing `validate_adapter_result` and later honesty checks. Deadline is rechecked after receive, decode, closed-wire validation, and reconstruction. The no-oracle import boundary is preserved.
- **Remove forgeable whole-bakeoff abort signals:** the `WORKER_TRANSPORT_FAILURE_EXIT_CODE` constant, the dedicated exit-code classification, the `transport_failure` envelope/status, and all claims that child send failure is trusted infrastructure are DELETED. An adapter may call any `os._exit(code)`; every child EOF/exit code is adapter-scoped `process_died` (NEVER `HarnessInfrastructureError`). Child `send_bytes` failure: the child closes and exits nonzero; the parent sees EOF/process death and classifies adapter-scoped `process_died`. Hostile/oversize child-controlled frame or ambiguous `recv_bytes(maxlength)` `OSError` is classified as adapter-scoped `malformed` (a child can induce it; the `OSError` message is NOT parsed). `poll` `OSError` remains infra (parent-local pipe state failure, demonstrably distinguishable — it occurs before any child bytes are observed). Only demonstrably parent-local setup/start failures and failed cleanup/reap/receiver-thread termination raise `HarnessInfrastructureError`. Process handle inspection failure attributable to parent runtime may be infra. Parent-owned queue/thread creation failure may be infra. NO child-authored envelope status can raise `HarnessInfrastructureError`.
- **Real adversarial self-tests:** a hostile canonical-looking return containing a nested custom class / dataclass subclass / mapping subclass / custom object with `__reduce__`, `__iter__`, a property, or a JSON trick NEVER executes code in the parent. Real spawned hostile hooks are used with a marker outside the child workspace to prove the parent did not execute it; child-local execution of arbitrary adapter code is expected and isolated. The result rejects as malformed/process failure. Exact canonical `AdapterResult` round-trips over JSON and remains accepted. Duplicate keys at outer and nested levels reject; NaN/Infinity reject; invalid UTF-8/trailing docs/wrong shape/extra/missing keys/wrong bool-int/custom type reject. Direct fake-transport regression tests cover the depth/count/string caps (`_MAX_STAGE_DEPTH` / `_MAX_STAGE_LIST_COUNT` / `_MAX_STAGE_STR_LEN`) and the `parse_constant` / `object_pairs_hook` paths. Child hook `os._exit(73)` and several arbitrary codes => `process_died`, never infra. Child EOF / no-send (the child closes the pipe or exits before sending) => `process_died`; the docs no longer claim a "real send failure test" because no test forces `conn.send_bytes` to raise inside a real spawned worker. Parent-side setup/start and unreaped cleanup still infra. Parent-observed over-limit `recv` and ambiguous `recv` `OSError` are adapter-scoped (no whole-bakeoff abort). `maxlength` is actually passed; at-bound behavior is covered. Repeated hostile/timeout runs leave no active children/receiver threads. Tests traverse `_execute_stage_isolated` / `run_adapter` where feasible, not only direct decoder validators.

## v12 closure — tighten the adapter-payload exception boundary; full-run continuation after hostile child exit

Phase A v12 closes three narrow final-review gaps in the v11 stage transport without adding algorithms, datasets, providers, product repo code, generic plugin/executor frameworks, or private runs:

- **Adapter-scoped parser exception boundary:** in `_wire_decode_envelope` and the `_receiver` thread, every known exception caused by received JSON bytes is converted deterministically to a `_WireError` then receiver outcome `malformed` — NEVER propagated to the receiver catch-all `pipe_error` -> `HarnessInfrastructureError`. Specifically converted: invalid UTF-8 (`UnicodeDecodeError`), `json.JSONDecodeError` / `ValueError` (including the Python 3.11+ oversized integer-token limit `sys.get_int_max_str_digits()`), `RecursionError` (deep nesting beyond the C parser recursion limit), `OverflowError` (numeric overflow), the duplicate-key `object_pairs_hook`, the `parse_constant` hook (NaN/Infinity), the depth/count/string caps in `_wire_validate_depth_and_primitives`, the exact-schema/reconstruction failures in `_wire_validate_envelope` / `_wire_reconstruct_adapter_result` / `_wire_reconstruct_candidate` / `_wire_reconstruct_fallback_record` / `_wire_reconstruct_binding_proposal`, and unexpected `TypeError` / `KeyError` / `AttributeError` / `IndexError` from reconstruction. A closed `_WIRE_CHILD_PARSE_EXCS` tuple is shared by every per-call `except` clause in the receiver. Genuinely parent-local `poll` OSError, queue/thread creation failure, setup/start launch failure, and unreaped-cleanup / receiver-thread-leak failures REMAIN infrastructure aborts — the boundary is scoped tightly around strict decode/parse/validate/reconstruct, NOT around all parent programming failures.
- **Full-run continuation after a hostile child exit (end-to-end):** a real spawned hostile hook that calls `os._exit(73)` yields a REJECTED `ValidatedRunRecord` with adapter `adapter_exception:process_died` failure category and an EMPTY `capability_ledger_summary` (only accepted records may publish a validated ledger), no `pack_status`, no `canonical_pack_hash`, and a `ResourceSample` with `query_seconds` present. A subsequent VALID adapter run in the SAME test process / bakeoff sequence executes and is ACCEPTED with `pack_status="ready"`. No `HarnessInfrastructureError` is raised and no child / receiver thread leaks. This proves whole-run continuation, NOT only direct `_execute_stage_isolated` classification — a hostile child exit is one rejected record, not an abort of the bakeoff.
- **Documentation honesty:** every stale v10 claim that a dedicated worker transport-failure signal or worker-send infra abort still exists is removed / superseded. v11/v12 truth: child EOF, exit, send failure, or ambiguous recv is adapter-scoped; only parent-local setup/poll/cleanup/reap/thread failure aborts. The docs do NOT claim a "real send failure test" unless one genuinely forces `conn.send_bytes` to raise inside a real spawned worker; the existing `close_without_send` / `os._exit` tests are EOF / no-send tests, not send-failure tests, and the wording is narrowed accordingly. Depth / count / string / duplicate-key / nonfinite claims are kept ONLY because compact direct fake-transport regression tests cover each: deep nesting (RecursionError), oversized integer (Python 3.11+ int-digit limit, feature-detected), depth cap (33 > `_MAX_STAGE_DEPTH=32`), oversized string (`> _MAX_STAGE_STR_LEN`), oversized list (`> _MAX_STAGE_LIST_COUNT`), nested duplicate keys (`object_pairs_hook`), and NaN/Infinity (`parse_constant`) all reject as adapter-scoped malformed (NEVER infra).

All prior v9/v10/v11 guarantees are preserved: full source-tree freeze, WSR confinement, pre-hook scan, special-file rejection before read, immutable post-hook scan, explicit proposal, harness-only `VerifiedEvidence`, pack rerender/recompute, accepted-only ledger, oracle scorer-only, exact report/matrix reconciliation, no pickle on the run-phase wire, no forgeable whole-bakeoff abort signal. Phase A public status remains strictly synthetic adapter-conformance readiness; no real fairness/product winner/default/operational claim. CI remains provider-free drift gate (`--check-drift`).

## B0 execution-substrate readiness

B0 records bounded engineering readiness for the Phase B scoring substrate only. Phase A remains contract `product_bakeoff_contract.v12` and synthetic-only; the public Phase A report, status, and counts (29 accepted / 57 rejected / 9 categories) do not change and make no product winner, default, or real-fairness claim. B0 is not S0-S5 tournament evidence. Nothing here is added to the canonical contract surface or the public report.

- **Harness-private accepted-output capture (Phase B scoreability):** a harness-private, oracle-free, in-memory, same-execution one-shot accepted-output capture (`PrivateValidatedOutputCapture` + `require_scoreable`) exists solely so Phase B can score the exact validated candidates/evidence/pack after a final source scan and run-record validation. It is NOT in the canonical contract surface (absent from `product_bakeoff_contract.__all__`), is NEVER persisted, is NEVER part of `ValidatedRunRecord` or the public report, NEVER imports the oracle, and exposes no public `commit()` or `reset()`. The sole mutator is the private one-shot `_commit_accepted(record, output)`, which binds the EXACT final `ValidatedRunRecord` object identity; `require_scoreable` enforces `record is committed_record` (identity, not equality), so the capture cannot be reused, reset, retried, or bound to a different record. A failed commit attempt is burned before validation (no retry); a successful commit cannot repeat.
- **Parent-owned CPU/RSS measurement:** the parent samples the direct worker's CPU and RSS through a fixed parent->child release barrier (`_STAGE_RELEASE_TOKEN`) so the successful child is guaranteed alive (blocked on the release) at sampling time, eliminating the post-exit race (Linux `/proc` gone, Windows handle race). The release token is a fixed opaque byte string the child never interprets; it is not adapter-authored JSON and is not negotiated. Unavailable measurement is explicit as `None`. Phase B scoreability requires that attempted stages carry non-None trusted (harness-measured) samples: an accepted `ok` record requires non-None `cpu_seconds` AND `rss_bytes` (missing metrics fail scoreability; the arm is never zero-filled or dropped silently). This is process-isolated CPU/RSS sampling on Linux/Windows; it is NOT a claim of perfect OS portability or of product resource results.
- **Persistent BM25 separated roots:** persistent BM25 supports separated `source_root` and `state_root` (CLI `--source-root` / `--state-root`). State artifacts live only at `state_root/.openlocus/index`; source/currentness checks (path safety, current-content re-read, currentness verification) are bound to `source_root`; the live doc count after updates is exact (read from a fresh post-commit `Searcher::num_docs()` summing live, non-deleted docs across segments); skipped-entry promotion rechecks current indexability under the same semantics as build/update (readable UTF-8 and nonempty, path-safe, policy-included), so a skipped entry that becomes readable is promoted even with an unchanged SHA; and `validate_separated_roots` fail-closes on bidirectional artifact/source overlap (`state_root/.openlocus/index` equal to, beneath, or containing `source_root`) plus symlink/canonicalization checks (dangling links and symlink loops in the artifact path or its ancestor chain are rejected; canonicalization through targets is enforced). `--state-root` requires `--source-root` and is rejected alone. Legacy colocated mode (no flags, `source_root == state_root`) remains behavior-compatible; its trace writes are now checked too (colocated commands are not literally unchanged).
- **Filesystem boundary (exact guarantees / non-guarantees) and trace routing:** persistent INDEX artifacts live only under `state_root/.openlocus/index`; best-effort persistent CLI telemetry traces, when safely writable, live only under `state_root/.openlocus/traces` and never fall back to source; trace failure warns/skips after the core command result. Exact guarantee: under a quiescent filesystem tree, pre-existing symlink / Windows reparse point / special-file / wrong-kind descendants and unsafe source-vs-artifact overlap fail closed; a full typed preflight happens before mutating any EXISTING index artifact; establishing a wholly absent `state_root` trust anchor may create its missing real-directory components before that typed preflight. Exact non-guarantees: no concurrent path-swap/TOCTOU resistance, hard-link or bind-mount defense, hostile/network filesystem defense, or OS sandbox claim. B0 remains engineering readiness only, not S0-S5 tournament/product/fairness evidence.

## Synthetic-only Phase A limitations

Phase A uses synthetic temporary repositories with deliberately unrelated fixture values. It does NOT clone external projects, rank real algorithms, change a product default, run providers, or claim product effectiveness. The threat model only protects against accidental contract leakage of scorer/oracle/path/excerpt/freshness facts into adapter outputs; it does NOT contain a hostile executable scanning the host machine. Adversarial adapters here test contract enforcement (rejecting bad outputs), not host sandboxing. Timeout enforcement is process-isolated with immediate termination (no grace period).

v6: `BakeoffVerifiedEvidence` is a **bakeoff-only schema** and is NOT production EvidenceCore. It uses unambiguous SHA-256 field/algorithm naming (`source_sha256`, `excerpt_sha256`) and tuple `why: tuple[str, ...]`. Exact production EvidenceCore projection (`content_sha` BLAKE3, `why[]` list, production channels) is **deferred to landing integration**; bakeoff results **cannot be passed directly** as production EvidenceCore. No BLAKE3 dependency is added.

Phase A public status is exactly synthetic adapter-conformance readiness. It must NOT claim product/algorithm readiness, real fairness, S0-S5 conformance, a winning/default stack, retrieval/coding improvement, real-repository robustness, supported languages/sizes, external-adapter readiness, production currentness correctness, or operational acceptance.
